# 浙江省慢病一体化管理监管平台：新版模块与指标建议

> 2026-10-29 产品建议稿。指标是产品候选口径，不代表省卫健已批准的考核指标。Demo 中所有数值、机构和整改事项均为模拟数据。

## 一、产品决策

**建设一个监管后台，并将“数据大屏”放在左侧菜单第一项。** 菜单依次为数据大屏、人群底数、一体化建设、管理过程、健康成效、整改督办；不再单设“监管总览”。唯一的建设上报入口位于“一体化建设”内部；数据接口状态作为内部质控信息，不单列左侧菜单。顶部显示系统名称、用户信息、原型说明和重置演示。后台支持省、市、县、机构逐级比较、建设核验、问题交办和整改复核。

理由：2025 年政策同时要求能力建设、路径/清单质控和健康改善评价；10 月 28 日会议要求从全省诊断底数看管理覆盖，穿透市、县、机构，并解决非本公司覆盖区县的数据归集。旧版大屏能展示部分两慢专档服务结果，但不能回答“全省有多少诊断人群尚未纳管、门诊是否真实建成且在运行、数据是否可信、谁负责整改”。

**核心管理链**：诊断人群底数 → 专档/签约/路径覆盖 → 一体化门诊建成与启用 → 路径节点与异常闭环 → 可评价健康结果 → 异常核验和整改。

## 二、模块与指标

“P0”是首期演示和数据对接优先项；“P1”在来源和规则确认后接入。比率统一展示分子、分母、统计期、数据覆盖率；跨区域比较仅针对同口径且已审核的数据。诊断人群、专档在管人群、入径人群是三层不同对象，不得互相替代或直接相加。

| 模块 | 指标 | 优先级 | 建议口径与管理作用 | 首选来源 |
|---|---|---|---|---|
| 全省底数 | 高血压确诊人数、糖尿病确诊人数、两慢病确诊去重人数 | P0 | 期末有效诊断、死亡/迁出等排除；同患去重。呈现疾病人群底数及市县差异。跨机构诊断去重、确诊有效性需省级主索引和规则确认。 | 省级区域平台/HIS 诊断、居民主索引 |
| 全省底数 | 两慢病专档有效在管人数 | P0 | 期末高血压或糖尿病专档有效在管患者去重人数；与确诊人群同源匹配，显示从确诊到在管的差额。 | 公卫/慢病管理系统 |
| 全省底数 | 确诊人群纳管覆盖率 | P1 | 同期确诊且有效在管人数/可纳管的确诊人数；“可纳管”资格与属地归属先定规则。用于发现服务缺口，不与旧版专档人数混称。 | 诊断、专档、主索引 |
| 全省底数 | 家医签约覆盖率、基层就诊率 | P1 | 前者为在管人群中有效签约人数/在管人数；后者为匹配人群基层门诊人次/全部门诊人次。按人和按人次分列。 | 签约、HIS/区域平台 |
| 门诊建设 | 应建设机构数、已建成一体化门诊数、建设覆盖率 | P0 | 已核验建成机构数/适用建设机构数；“应建设”名册由省级确认。区分自报、县审、市审、省抽核。90% 目标仅为会议口述，待政策或客户确认后显示目标线。 | 机构名册、建设申报、审核记录 |
| 门诊建设 | 基本保障清单达标机构数、强化功能清单完成机构数、鼓励探索清单完成机构数 | P0 | 三类是**清单层次**，不是互斥的三种门诊类型。逐项记录符合/不符合/不适用、证据、审核结论；不能将三类数量相加作为总门诊数。 | 建设清单与现场证据 |
| 门诊建设 | 建设证据完整率、抽核一致率 | P0/P1 | 必交证据齐全机构数/应提交机构数；抽核一致机构数/已抽核机构数。照片只能证明部分外观与配置，不能单独证明持续运行。 | 图片、视频、时间地点、审核记录 |
| 门诊运行 | 有效启用门诊数/率 | P0 | 建成门诊中统计期内存在真实两慢病就诊且有有效服务记录的机构数/已建成门诊数。最小就诊量阈值与观察期需确认。 | HIS、一体化门诊系统 |
| 门诊运行 | 两慢病门诊就诊人次、同比变化 | P0 | 一体化门诊就诊事件去重后的人次；同比使用同季度/半年/年度，并展示上期基数。不能用“登录次数”代替。 | HIS/就诊流水 |
| 门诊运行 | 诊间随访率 | P0 | 近三个月两慢病诊间随访人次数/辖区两慢病总随访人次数。2025 清单的强化功能、鼓励探索对应 15%、30% 参考要求；不把它们错误解释为全省统一考核线。 | 随访系统、HIS |
| 路径质控 | 入径人数、入径率 | P0 | 统一建议按**人**：统计期内符合纳入条件且完成规定路径进入事件人数/应入径在管人数。旧余杭版本以每季度同日就诊+有效诊前为判定，省级需确认可跨厂商实现的最小事件标准；另列“数据可计算机构数”。 | HIS、慢病路径事件、专档 |
| 路径质控 | 节点执行率 | P0 | 已完成的应执行路径节点数/同期应执行节点数，按诊前、诊中、诊后拆解。每次/季度/年度项目、适用人群和例外调整需配置，不能简单按 31 项平均。 | 诊前采集、临床路径、随访 |
| 路径质控 | 核心监测完成率、漏测率 | P0 | 在应检时窗内完成有效项目的人数/应检人数；漏测=应检未完成/应检人数。按血压、血糖、HbA1c、血脂、BMI/腰围分项；数据缺失与临床不适用分开。 | HIS/LIS/体检/设备 |
| 路径质控 | 异常发现后复查完成率、异常闭环率 | P0/P1 | 前者为发生有效异常且到复查时限的事件中完成同项目复查的事件数/应复查事件数；后者要求记录处置、复测/转诊结果与责任人。不能以“已提醒”当闭环。 | 检验检查、随访、转诊事件 |
| 协同服务 | 上转实际到诊率、下转接续率 | P1 | 上转实际到诊/有效上转单；下转后基层接续服务/有效下转单。需跨机构转诊单及就诊匹配，未接通平台时不显示假零。 | 转诊平台、HIS |
| 健康结果 | 血压控制率、血糖控制率 | P0 | 分病种按当期**有有效检测且目标可判定**人群计算；并列检测覆盖率、未检测人数，避免“只测好控制者”使达标率虚高。控制目标及时间窗经临床确认。 | HIS/LIS/随访/体检 |
| 健康结果 | 核心指标改善率 | P1 | 基线异常且期末有效可评价患者中，按同一指标、可比时间窗达到预定改善标准者/可评价者；先分项展示，综合“任一项改善”需防止掩盖其他指标恶化。 | 纵向检测记录 |
| 健康结果 | 可评价样本占比 | P0 | 同时有有效基线与期末记录的人数/应评价人数。改善结果旁必须展示，避免样本选择偏差。 | 检测记录、专档 |
| 数据治理 | 市县接口接入覆盖率、接口更新及时率、关键字段完整率 | P0 | 分别展示数据高铁、我方系统、第三方慢病系统的接入、更新、可计算状态。缺接口/断流不记为零业绩。 | 数据高铁与区县系统接口日志、校验结果 |
| 数据治理 | 指标可比机构数、接口异常机构数、建设上报待核验批次 | P0 | 只有通过口径和质量门槛的数据才参与横比；建设申报单独保留原始材料、审核轨迹。 | 接口质控、建设上报审核 |
| 监管执行 | 待整改机构数、逾期事项数、复核通过率 | P0 | 从异常证据生成责任事项，按责任方/截止日/复核结论统计；整改完成以复核通过为准。 | 督办台账 |

### 旧版指标的处理

- **沿用并升级**：一体化门诊覆盖、两慢病专档、基层就诊、入径、节点执行、诊间随访、血压/血糖控制、健康监测改善。
- **新增省级必需层**：确诊人群去重底数、确诊到在管的覆盖缺口、建设证据与审核、有效启用、可评价样本、数据可比性、整改闭环。
- **降为专题或后期**：区域健康指数、并发症发生率、复杂红黄绿分层、全量 31 项逐项省级排名。原因分别是解释或数据门槛高、需要长周期校正、会议要求先切开主动风险分级，以及 31 项存在适用条件和不同频次。

## 三、唯一上报与其他数据接入

**唯一允许区县上报的是一体化门诊建设情况。** 区县不能手工填报确诊人数、专档人数、入径率、节点执行率、控制率、改善率等业务指标，也不设置过渡期汇总包上传。无接口时显示“待接入/不可计算”，不以人工报数填补。

| 数据域 | 获取方式 | 需要的信息 | 质量控制 |
|---|---|---|---|
| 一体化门诊建设 | 区县在后台申报，建设或变更时更新 | 行政区划代码、机构统一代码、机构名称和地址、建成日期、2025 年版基本保障/强化功能/鼓励探索清单逐项结论、联系人、机构名称与门诊标识同框照片、诊前中后环境及设备照片 | 必填项与重复机构校验；县级确认、市级复核、省级抽核；照片只证明部分建设事实，不能证明运行。 |
| 确诊、就诊、检验检查等省级公共数据 | 按授权从浙江省数据高铁取数 | 脱敏患者主键、机构与地区代码、诊断/就诊/检验检查事件、发生时间、项目代码与单位 | 主索引去重、字段标准化、数据覆盖与更新时间监测。 |
| 使用我方慢病系统的区县 | 直接对接我方现有系统 | 专档、路径入径、诊前中后节点、随访、异常处置、转诊等事件及规则版本 | 事件 ID 去重、时间顺序、适用资格和规则版本校验。 |
| 使用其他慢病系统的区县 | 对接当地正在使用的慢病管理后台系统 | 与我方区县同一套事件与代码标准，通过接口映射其现有字段 | 逐区县验证可用字段、缺项和接口更新；未达到可比条件时不参与区域横比。 |

**建设上报流程**：省级发布清单版本与申报规则 → 区县填机构与建设项目、上传照片 → 系统预检 → 县级确认 → 市级复核 → 省级抽核/退回 → 发布建设结果。**其他数据流程**：数据高铁/我方系统/第三方系统接口 → 统一身份与机构代码 → 校验、去重、计算指标 → 标记数据覆盖与可比性。整改督办只记录管理处置状态，不开放业务指标上报，也不允许借此修改原始业务数据。Demo 只模拟建设申报的本地预检，不传真实患者数据或文件。

## 四、页面结构与首期界限

1. **数据大屏**：左侧为患者底数、纳管情况和覆盖缺口，中央为浙江省地图，右侧为门诊建设、有效启用、路径管理、分项健康改善和本期需关注事项。地图可直接切换各市与全省区县，悬浮卡展示所指区域的多项数值。所有数字是模拟数据。
2. **人群底数**：确诊、有效在管、病种重叠、确诊与在管差额、分病种纳管和市县差异；按机构层级查看。原型使用自洽的模拟数据，正式数据须来自数据高铁与区县系统接口。
3. **一体化建设**：建设概况与建设上报两个内页。概况展示基本保障清单达标、强化功能清单完成、鼓励探索清单开展的机构数，并区分建设和使用；上报是唯一业务数据上报入口。
4. **管理过程**：入径、诊前/诊中/诊后节点、核心监测漏测、异常复查、诊间随访；从市县到机构看断点。
5. **健康成效**：血压、血糖的检测覆盖率、控制率和改善率成组展示，并列糖化血红蛋白与低密度脂蛋白改善率、可评价样本占比和地区比较；长期趋势及病例组合校正作为后续能力。
6. **整改督办**：异常转事项、责任归属、复核和回看指标变化；不提供业务指标填报。

**穿透层级的会议原意**：省级视角至少直接看到市、县两级差异，不必先进入市页面才能看到县。当前对客户可承诺继续钻到社区卫生服务中心等机构；患者明细不是省级默认层级。“每个层级固定向下两层”并非会议确定的统一规则。

**地图交互**：省级地图提供“各市 / 全省区县”两个视图，无须先点进市就能看到县区差异。两种视图悬浮分别显示市或县区的确诊、在管、门诊建设、启用、入径与血压改善等数值，点击进入地区详情。原型现已接入阿里云 DataV 的 11 个地市与 90 个区县边界；区县指标仍是依据模拟地市数据分配生成的演示值。正式上线需要逐县真实指标、机构编码映射、行政边界版本核验及数据可比性校验。

### 人群底数页的管理设计

**定位**：回答“全省有多少两慢病确诊人群、结构是什么、基层管理承接了多少、差异在哪些市县”。它是服务对象的底座，不能把一体化门诊建设数或专档在管数当作全省慢病底数。会议要求按诊断确定底数，再把确诊、在管和路径管理拆开观察；2025 年一体化门诊标准与医防融合路径意见则提供后续服务承接与质量管理的政策背景。下表是产品建议，并非已批准的省级考核口径。

| 管理问题与痛点 | 首期指标 | 页面表现形式 | 管理价值与后续动作 |
|---|---|---|---|
| 全省到底服务多少人，两个病种是否重复计数？ | 两慢病确诊去重人数；高血压、糖尿病确诊人数；两病同患人数及占比 | 1 个总量主数字 + 三段病种结构条；分病种数作为辅助标注 | 建立跨病种、跨机构去重底数；识别共病负担，指导资源配置。 |
| 现有慢病体系承接了多少确诊人群？ | 两慢病有效在管专档去重人数；总体、高血压、糖尿病专档覆盖率 | 总量主数字 + 三条横向覆盖进度条 | 看总覆盖与病种不均衡，区分确诊规模和实际管理规模。 |
| 哪些人群值得继续核查？ | 确诊与在管差额；两病同患专档人数；分病种专档人数 | 数值对照条，点击进入地区差异 | 形成核查线索；差额不直接当作“未纳管人数”。须同人匹配并排除不适用者。 |
| 全省差异集中在哪里，能否直达县区？ | 市、县的确诊去重、在管、差额与覆盖率 | 地市 / 全省区县切换的比较表，按所选机构范围联动 | 省级直接发现县区差异，进入机构核查接口、承接能力和服务缺口。 |

**下一阶段可补充**：年龄段、性别、城乡、基层机构承接结构及新确诊人群变化；前提是数据高铁与区县系统能提供统一、可比、可追溯的字段。未经统一标准的红黄绿主动风险分层不进入首期省级底数页。确诊、在管、路径三层数值之间不能直接推断个体状态，正式分析需同一患者主索引关联。

### 数据大屏的管理价值

| 大屏内容 | 管理者要回答的问题 | 产生的管理动作 |
|---|---|---|
| 确诊、专档、确诊与在管差额、双病同患 | 全省两慢病规模是多少，服务覆盖缺口和复杂共病人群在哪里？ | 核查差额较大的市县、专档匹配与承接能力 |
| 建设覆盖、有效启用、路径入径 | 门诊是否建成、真正运行，并把在管患者带入规范管理？ | 对建而未用、已运行但入径不足的机构发起核验 |
| 血压/血糖改善率及可评价样本 | 管理行为是否带来可测的健康变化，结果是否有足够样本支撑？ | 进入健康成效页核查检测覆盖、改善阈值和异常地区 |
| 地图多指标悬浮及本期需关注 | 省内差异发生在哪个市县，当前应优先处理什么？ | 从地图进入市县机构明细，形成督办事项并复核 |

**人群底数页的重点**：先看确诊去重总数及高血压、糖尿病、双病同患结构；再看有效在管及分病种覆盖；最后比较各市县的确诊与在管差额。差额不直接等同“未纳管人数”：必须先完成同一患者匹配、死亡/迁出等排除和可纳管资格确认。正式版还应在数据可用后增加年龄、性别、城乡及重点人群分布，帮助配置基层服务资源，但不以没有统一标准的红黄绿分层替代底数。

**健康成效页的重点**：按血压、血糖等具体项目并列展示检测覆盖、控制和基线到期末的改善，同时展示可评价样本。检测不足时不能只报告控制率；改善率需基线异常、同人同项目、可比观察窗和临床确认阈值。省级重点看趋势与地区差异，定位服务执行充分但成效未改善的地区；HbA1c、LDL-C 等项目随接口和规则成熟后扩展，不把“任一项改善”合成一个容易掩盖退步的总分。

**建设分类口径**：10 月 28 日会议中提到“基本型、鼓励型、探索型”的近似说法，但带有“好像”的不确定表述。《浙江省基层医疗卫生机构慢性病一体化门诊建设标准和服务规范（2025 年版）》第 4 页及附件第 6-9 页的正式名称是**基本保障清单、强化功能清单、鼓励探索清单**。文件提出因地制宜、逐步落实，并未规定三种互斥的门诊认证类型。Demo 因此按三类清单展示完成/开展机构数，不能相加；省级达标判定规则仍待确认。

**两项待确认**：①“2026 年覆盖 90%”在 2025 年版政策正文未查到，应向省级确认目标来源、分母和适用机构；②省级确诊底数、跨机构主索引及数据高铁字段的可用性，决定“确诊→纳管”链能否首期真实上线。上述未确认内容在 Demo 仅作方案表达。
